# Complete CmdDb capture work admission

`--wifi-power-cmddb-budget-admission` is default OFF and requires the full
bounded capture-only path. It rejects the first-node planned-stop mode. The
existing power writer, original Query and original descriptor getters remain
unreachable in this scope. This is one integrated full-read candidate, not a
standalone inventory or benchmark boot.

Before any private Create, a separate resident Core record/context and one-use
ticket bind the actual LoadedImage. Its guarded original GetMemoryMap, full
five-range source and ConfigurationTable checks establish the same read-only
authority as the original context. Three fresh complete hash samples retain
all five digests and architectural counter observations. A second guarded map,
complete source/config snapshot, exact map key/bytes, released-lock observation,
TPL and owner comparison retire this RO-only phase. Phase3 explicitly means
RO retirement without getters; it cannot impersonate the ordinary eight-query
GCD phase2. Neither the private nor the final Clock/GCD ticket is reset/rebased.

The conservative work estimate is `80 * max(sample_ticks) + 480000`, admitted
only at or below 2400000 ticks at the already required 19.2MHz. The80 count
includes all74 full-capture Core checkpoints plus six original private/open/
reader checkpoints. The25ms reserve and125ms planning limit do not change the
original200ms runtime gate. Samples are observations and this estimate is not
a mathematical upper bound on future latency. Actual completion must still
pass every original current source, byte, owner, counter, FP/TPL, UNKNOWN and
retirement gate. No hash/checkpoint is cached or omitted during the full read.

A clean budget decline is possible only after complete RO retirement, before
any client exists. It does not start the client, retry, switch policy or claim
a database read. Any partial original call, changed source/context/map, late
counter, failed restoration or reentry remains sticky unsafe and reaches the
parent RAM-only quarantine. No cleanup, reset, firmware output or ACK is added
to that path. The complete31552B RAW_V1 is included in the log capacity assert
and exported beside the unchanged full client/path RAW records when safe.

This feature grants no DRV2/EE/EL3/VMID/MPU/DMA/rail authority. It enables no
MSS start, NV service, radio, scan, join or data operation. Physical hash samples
and a complete actual namespace/database capture remain required evidence.
