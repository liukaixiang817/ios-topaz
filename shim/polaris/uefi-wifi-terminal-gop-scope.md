# Terminal numeric evidence for the current Wi-Fi diagnostic

This new default-OFF scope addresses the absence of observable failure records
after0176. It does not claim that0176 reached a particular predicate or that
Wi-Fi works. It requires the explicit same-private masked database diagnostic;
the power/CPU/access implementation, original200ms lifetime, READ50ms/25ms work
reserves and every UNKNOWN/restore gate remain unchanged.

The [UEFI GOP specification](https://uefi.org/specs/UEFI/2.10/12_Protocols_Console_Support.html)
provides a linear framebuffer for direct boot-software access. This is a display
contract, not a DRV2, EE/EL3, VMID, MPU, radio or DMA grant. The phone's existing
GOP admission and native video handoff already use9d400000/1080x2160/stride1080.
This scope does not treat a Reserved map descriptor as free memory or infer a
framebuffer grant merely from AT success. It additionally binds the actual GOP
protocol/mode/info objects obtained by the resident loader, their complete
headers, existing fixed geometry and native-CPU-not-issued flag.

Before any Wi-Fi work, a separate normal-IRQ admission saves/restores the
original GetMemoryMap call's actual FP/context, validates its full map and
BootServices ownership of the resident evidence/native flag and GOP headers,
checks current architecture, and captures NS normal-memory read/write AT/PAR
evidence for every framebuffer page to be touched. No pixel is written here.
An ordinary missing/unsupported display condition refuses the diagnostic while
no private client or CPU interval has opened. An uncertain foreign return
retains UNKNOWN and enters the same terminal hold. Reentry cannot renew it.

Only after complete power RAM reports and the terminal all-DAIF/G1 mask, the
new path can draw16 rows of literal labels and resident numeric fields. It
rechecks the literal native flag/self/GOP binding, current architecture, exact
GOP headers, read/write translations and exact PAR restoration. It checks all
pages before the first pixel and checks each page again immediately before its
stores. Only the576x384 rectangle at48,96 is written, with monochrome glyphs
identical in both supported GOP pixel formats. Cache cleaning stays inside the
same checked framebuffer pages. Raw translations, errors, partial counts,
outstanding page, pixel counts and completion are retained in a distinct
WIFI_TERMINAL_GOP_RAW_V1 actual-C record. Log capacity includes two full copies.
Zero or unused fields are displayed beside attempted/issued state, not called
successful hardware observations. The screen explicitly says NOT WIFI.

The terminal50ms rendering bound is independent terminal work; it never opens,
resets, renews or resumes a private/final GCD ticket. No GOP/Blt/Console/USB,
foreign method, allocation, SMC, Stall, cleanup, response ACK, reset or CPU/
private restoration follows UNKNOWN. Completion or failure of the local draw
both proceed to the existing nonreturning WFE hold. A partial draw is neither
restored nor labelled complete. Normal success draws no pixels and preserves
the normal wallpaper, clock, battery and WLED flow.

This is not an exception handler. A nonreturning call, synchronous fault before
the hold, changed/unsupported display mapping, unknown architecture or failed
display admission can still prevent a visible record. No physical display
success, root cause, READ/vote/MSS/NV or network claim follows from software
tests or compilation. A physical candidate still requires a new exact host
profile, affected checks/two serial wholeEFI-XNU models, original codec,
independent freeze/once helper, fresh root/NV qualification and actual Polaris
FASTBOOT. The0176 session remains consumed.
